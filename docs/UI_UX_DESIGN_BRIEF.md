# MandiWise — UI/UX Design Brief

**Document:** UI/UX Design Brief  
**Project:** MandiWise  
**Version:** 2.0  
**Status:** Design Direction Approved  
**Primary Platform:** Responsive Web Application  
**Frontend Stack:** React, TypeScript, Tailwind CSS  
**Design Language:** Premium, Nature-Inspired, Cinematic, Editorial, Minimal  
**Primary Design Philosophy:** Apple-inspired clarity and craftsmanship

---

# 1. Purpose of This Document

This document defines the visual identity, user experience principles, interface structure, component styling, motion design system and interaction guidelines for MandiWise.

It serves as the primary design reference for:

- UI development.
- Frontend implementation.
- Component creation.
- Landing page design.
- Dashboard design.
- Animations and transitions.
- Responsive behaviour.
- Visual consistency.
- Design decisions made by AI coding assistants.

Every interface developed for MandiWise must follow this document.

The objective is not merely to create a functional agricultural application. The objective is to build a visually sophisticated, intuitive and memorable product.

The application should feel like a carefully designed commercial product rather than a conventional academic project.

# 2. Overall Design Vision

MandiWise should combine three qualities:

### 2.1 Premium Product Experience

The interface should feel refined, modern and professionally crafted.

Characteristics:

- Strong visual hierarchy.
- Beautiful typography.
- Consistent spacing.
- Carefully designed components.
- Subtle depth and layering.
- Smooth interactions.
- Thoughtful use of whitespace.
- High-quality visual assets.
- Consistent design language across every page.

### 2.2 Nature-Inspired Visual Identity

Agriculture should influence the visual identity without making the application look outdated or overly traditional.

Use inspiration from:

- Karnataka's agricultural landscapes.
- Green fields.
- Trees and foliage.
- Morning sunlight.
- Earthy textures.
- Natural colour palettes.
- Vegetable and crop imagery.
- Rural landscapes.

Avoid excessive agricultural symbols such as tractors, cartoon farmers, random leaves and generic farming illustrations.

The agricultural identity should be sophisticated rather than literal.

### 2.3 Data-Driven Interface

MandiWise is ultimately a decision-support platform.

The visual experience must make important information easy to understand:

- Market prices.
- Transportation expenses.
- Expected gross revenue.
- Estimated net earnings.
- Market comparisons.
- Historical trends.
- Quality assessment results.
- Agricultural insights.

Beautiful design must never compromise information clarity.

# 3. Design Philosophy

## 3.1 Apple-Inspired Design Principles

MandiWise should follow the underlying design philosophy of Apple's Human Interface Guidelines.

Reference:

https://developer.apple.com/design/human-interface-guidelines/

The intention is to adopt Apple's design principles, not reproduce Apple's interface.

### Clarity

Every element must communicate its purpose.

- Important information should receive visual priority.
- Buttons should have obvious actions.
- Navigation should be predictable.
- Charts should be understandable.
- Financial information should be clearly labelled.

### Simplicity

Remove unnecessary visual complexity.

- Avoid cluttered dashboards.
- Avoid excessive cards.
- Avoid unnecessary borders.
- Avoid redundant information.
- Avoid complicated navigation structures.

Simplicity does not mean removing useful functionality.

### Consistency

Maintain a unified design system.

- Consistent spacing.
- Consistent typography.
- Consistent button styles.
- Consistent component behaviour.
- Consistent animations.
- Consistent colours.

### Craftsmanship

Every visible detail matters.

Pay attention to:

- Alignment.
- Spacing.
- Typography.
- Border radii.
- Shadows.
- Icon sizing.
- Animation timing.
- Hover states.
- Loading states.
- Empty states.
- Error states.

### Delight

The application should feel enjoyable to use.

Use thoughtful transitions, interactive elements and small moments of visual delight.

The experience should feel alive without distracting users from their tasks.

# 7. Hero Section — Primary Visual Identity

The landing page hero is one of the most important parts of MandiWise.

It must immediately communicate the identity of the product.

## 7.1 Approved Visual Direction

The preferred direction combines:

**Direction 1: Cinematic Karnataka Countryside**

AND

**Direction 3: Sophisticated Editorial Agricultural Illustration**

The result should be an original, cinematic, layered illustration of an agricultural landscape.

It should feel artistic, atmospheric and premium.

It should not look like a generic stock image or a childish cartoon.

## 7.2 Visual Concept

Imagine an early morning in the Karnataka countryside.

The landscape contains:

- Rolling agricultural fields.
- Distant hills.
- A large distinctive tree.
- Layered vegetation.
- Small agricultural pathways.
- Soft morning sunlight.
- Atmospheric mist.
- Subtle environmental details.
- Natural depth and perspective.

The illustration should have:

- Sophisticated hand-painted textures.
- Layered foreground and background elements.
- Beautiful lighting.
- Atmospheric depth.
- Carefully balanced composition.
- Muted natural colours.
- Subtle artistic imperfections.

A gentle illustrated aesthetic is encouraged.

However, do not directly imitate Studio Ghibli or any specific animation studio.

The objective is to create an original MandiWise illustration style.

## 7.3 Hero Composition

The hero should be visually rich.

Suggested composition:

- Full-width cinematic landscape.
- Large heading positioned where text contrast is strongest.
- Short supporting description.
- Primary call-to-action.
- Secondary call-to-action.
- Optional subtle navigation transition into the main application.

Suggested heading:

"Make every harvest count."

Supporting text:

"Discover better markets, understand your potential earnings and make informed selling decisions."

Primary CTA:

"Find the Best Mandi"

Secondary CTA:

"Explore Market Prices"

The exact copy can be refined later.

## 7.4 Hero Animation

The hero must not be a static background image.

It should have carefully designed environmental motion.

Possible animations:

1. Leaves gently falling from the large tree.
2. Subtle movement in foreground vegetation.
3. Slight atmospheric movement in distant mist.
4. Slowly shifting sunlight or lighting effects.
5. Gentle movement of clouds where appropriate.
6. Subtle depth movement between foreground and background.
7. Smooth appearance of heading and supporting text.
8. Staggered appearance of call-to-action buttons.

The movement should be atmospheric and natural.

Avoid making every object move simultaneously.

The animation should create the feeling of a living landscape.

## 7.5 Hero Interaction

Explore:

- Gentle parallax when scrolling.
- Subtle depth response to pointer movement on desktop.
- Smooth transitions between hero and the next section.
- Scroll-triggered appearance of supporting content.
- Subtle movement of visual elements based on scroll position.

All interactions must remain smooth and must not interfere with reading or navigation.

## 7.6 Hero Asset Requirements

The hero illustration should ideally be a custom-generated visual asset.

Do not rely on a random stock photograph.

The visual asset should be designed specifically for MandiWise.

If using a layered illustration:

- Separate foreground, middle-ground and background elements where practical.
- Keep the main text region visually uncluttered.
- Ensure the image works on desktop and mobile.
- Use appropriate responsive crops.
- Optimise image sizes.
- Avoid excessive image loading time.

The illustration should establish the visual identity used throughout the application.

# 9. Motion Design System

**Motion and animation are important design features of MandiWise.**

Do not treat animation as an optional decoration to be added at the end.

Motion must be considered during component design and implementation.

The application should feel fluid, responsive and alive.

However, animation must serve the experience.

The objective is not to animate everything randomly. It is to create a cohesive motion language across the entire product.

## 9.1 Motion Philosophy

Use motion to:

- Establish visual hierarchy.
- Guide user attention.
- Communicate state changes.
- Connect different screens.
- Make interactions feel responsive.
- Make data easier to understand.
- Create emotional engagement.
- Improve the perceived quality of the product.

Animations should feel smooth, intentional and polished.

## 9.2 Animation Categories

### A. Page Transitions

Navigation between major pages should feel smooth.

Explore:

- Subtle fade transitions.
- Slight vertical movement.
- Shared-element transitions where practical.
- Smooth content replacement.
- Animated page entry.

Avoid harsh transitions or unnecessary full-screen animations.

### B. Scroll-Triggered Animations

Use scroll-based animation selectively.

Examples:

- Sections appearing with a subtle reveal.
- Cards entering with staggered timing.
- Illustrations moving at different parallax speeds.
- Charts revealing as they enter the viewport.
- Statistics counting up when first displayed.
- Feature sections transitioning naturally into view.

Do not animate every paragraph or label.

### C. Micro-Interactions

Interactive components should provide immediate feedback.

Examples:

- Buttons gently scale or change elevation on hover.
- Pressed buttons respond with subtle compression.
- Cards lift slightly when interactive.
- Navigation indicators transition smoothly.
- Tabs animate between selected states.
- Dropdown menus appear smoothly.
- Tooltips fade into view.
- Toggles animate naturally.
- Form fields respond to focus.
- Checkboxes animate when selected.

### D. Data Animations

MandiWise contains important numerical information.

Use animations to make data presentation engaging.

Examples:

- Market prices counting into their final values.
- Earnings values animating when results load.
- Charts drawing their lines.
- Bars growing from zero to their actual values.
- Comparison indicators transitioning between markets.
- Ranking positions appearing smoothly.
- Percentage changes animating into view.

Numerical animations must never misrepresent the actual values.

The final displayed value must always be accurate.

### E. Loading Animations

Avoid generic spinning loaders wherever a more informative loading experience is possible.

Examples:

- Skeleton loading.
- Animated chart placeholders.
- Subtle agricultural illustration animations.
- Progress indicators for longer processing tasks.
- Step-based processing indicators for image assessment.

Do not display fake progress percentages.

### F. Environmental Animations

Use these primarily in the landing page and selected visual sections.

Examples:

- Falling leaves.
- Moving vegetation.
- Subtle atmospheric effects.
- Soft sunlight transitions.
- Layered parallax.
- Gentle cloud movement.

These should remain subtle enough not to distract from the interface.

## 9.3 Motion Timing

Use these as starting guidelines, not rigid restrictions.

| Interaction               | Suggested Duration |
| ------------------------- | ------------------ |
| Button feedback           | 120–200 ms         |
| Hover transitions         | 150–250 ms         |
| Dropdown appearance       | 180–250 ms         |
| Card transitions          | 200–350 ms         |
| Page transitions          | 250–450 ms         |
| Modal appearance          | 200–300 ms         |
| Chart animations          | 500–900 ms         |
| Hero environmental motion | Continuous, slow   |
| Scroll-based reveals      | 400–800 ms         |

Use natural easing curves.

Avoid linear motion for most interface transitions.

Suggested easing:

- Ease-out for entering elements.
- Ease-in for exiting elements.
- Ease-in-out for movement between states.
- Custom spring-like motion for selected interactive components.

## 9.4 Animation Technology

Preferred options:

- Framer Motion / Motion for React.
- CSS transitions and keyframes.
- GSAP where advanced timeline or scroll-driven animation genuinely requires it.

Use the simplest suitable tool.

Do not introduce multiple animation libraries without a clear reason.

Avoid unnecessary JavaScript animation loops.

## 9.5 Performance and Accessibility

Animation quality must not compromise application performance.

Requirements:

- Prefer transform and opacity animations.
- Avoid excessive layout-triggering animations.
- Lazy-load heavy visual assets.
- Avoid excessive simultaneous animations.
- Ensure mobile performance.
- Support reduced-motion preferences.
- Provide static alternatives where necessary.
- Avoid flashing effects.
- Keep essential information visible without animation.

Respect the user's `prefers-reduced-motion` setting.

Reduced-motion support should simplify nonessential animation rather than break functionality.

# 12. Data Presentation and Trust

MandiWise must communicate the reliability and limitations of its data.

Use consistent visual labels.

| Label      | Meaning                                                    |
| ---------- | ---------------------------------------------------------- |
| Actual     | Recorded information from the stated source                |
| Historical | Information from an earlier observation period             |
| Estimated  | Calculated estimate, such as transport cost                |
| Predicted  | Model-generated future estimate                            |
| Sample     | Demonstration data                                         |
| Verified   | Information that has passed a defined verification process |
| Unverified | Information not yet verified                               |

Never use colour alone to communicate these statuses.

Every important price should have an associated observation date and unit.

Missing data must not be represented as zero.

Do not label information as live unless the underlying source genuinely supports live updates.

# 17. Design Implementation Rules

These rules apply to all frontend development.

1. Build a consistent design system before implementing every page independently.
2. Define reusable colour, typography, spacing, radius and shadow tokens.
3. Use reusable components.
4. Avoid hardcoding inconsistent styles across pages.
5. Follow the approved visual direction.
6. Do not use generic dashboard templates without substantial customisation.
7. Do not use plain green backgrounds as a substitute for visual design.
8. Use the custom agricultural illustration style for brand identity.
9. Implement animations as part of component development.
10. Optimise animations for performance.
11. Ensure all pages are responsive.
12. Maintain accessibility.
13. Avoid unnecessary visual clutter.
14. Do not invent data to make the UI look populated.
15. Do not display unimplemented features as functional.
16. Do not sacrifice usability for visual effects.

- Typography.
- Spacing.
- Colour.
- Illustrations.
- Motion.
- Transitions.
- Responsiveness.
- Interaction feedback.

### Animation Quality Requirement

Do not omit animation simply because a static implementation is easier.

Consider appropriate animation for every meaningful interaction and visual section.

However, do not add motion that reduces usability, accessibility or performance.

### Reference Requirement

Use the reference products in this document as design inspiration.

Do not reproduce their interfaces.

MandiWise must have its own distinctive identity.

# 20. Final Design Direction

The final MandiWise experience should combine:

**Apple:** Design philosophy, clarity and craftsmanship.

**Linear:** Application layout and interface organisation.

**Stripe:** Financial data presentation and visualisation.

**John Deere:** Agricultural context.

**Original MandiWise identity:** Cinematic Karnataka landscapes, sophisticated editorial illustrations, nature-inspired colours and a carefully designed motion language.

The landing page should immediately establish a memorable visual identity through its cinematic illustrated landscape.

The application itself should remain clean, intuitive and data-focused.

Motion should be treated as a first-class part of the experience, not an afterthought.

The final product should feel:

- Premium.
- Modern.
- Beautiful.
- Fluid.
- Intelligent.
- Trustworthy.
- Agricultural without being outdated.
- Technologically advanced without being intimidating.

**The guiding principle: MandiWise should be as delightful to use as it is useful to farmers.**
